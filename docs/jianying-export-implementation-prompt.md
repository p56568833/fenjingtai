# 分镜台 → Mac 剪映草稿：实施提示词与验收约定

设计日期：2026-10-18。以下内容可以整体交给实施 AI。本文是开发任务书，尚未实现或验证剪映草稿导出。

## 1. 你的任务与完成标准

请在现有「分镜台」中实现「导出到剪映」：用户在分镜台排好素材后，生成可被 **Mac 剪映专业版打开并继续编辑的新草稿**。主画面、素材先后、源片段裁剪、时间位置、留白、定格补满、口播音频应准确带过去，避免用户重新拖素材、重新排时间。

产物必须是可编辑草稿，不是把全片合成为一个 MP4，不是素材清单，也不是分镜台自己的项目 JSON。素材应作为独立片段出现，进入剪映后仍能移动、替换和裁剪。

先完成目标版本的最小兼容性实证，再实现完整功能。代码测试通过、JSON 合法、文件已生成，都不等于剪映兼容性通过。最终必须在真实剪映中打开、播放、编辑、保存、关闭后再次打开验证。

此次交付是本地实现和可验收成果。不要自行发布 GitHub Release、推送代码或替换正式安装应用；如用户后续另有明确指示，以用户指示为准。可以用隔离预览与测试环境验证。没有真实剪映验证条件时继续完成独立可做的工作，交付时明确“待实机验收”，不得宣称功能全部完成。

## 4. 产品体验：一个入口，一次设置，后续快捷生成

在既有「导出」菜单中添加「导出到剪映」，与现有风格一致。不要新增常驻侧栏、大型工程管理页或第二套剪辑界面。

首次打开使用紧凑弹窗，显示：

- 目标：Mac 剪映专业版；可识别时展示实际版本与兼容状态。
- 草稿名称：默认项目名称，可编辑。
- 保存方式：默认「加入本机剪映草稿」，另提供「保存草稿文件夹」用于交付或手动放置；后者不能假装已经加入剪映。
- 素材策略：首版默认随草稿复制所需素材，显示大致体积。不要把路径、序列化字段、适配器版本等内部概念堆给用户。
- 摘要：画面数、总时长、口播是否包含、时间来自字幕还是估算、需要处理的问题。
- 「更多设置」收起画幅、帧率、字幕及备选素材选项。首次默认 1920×1080、30 fps；提供 9:16、1:1 和经过验证的常见帧率。参数影响导出草稿，不改变原项目排布。

正常主按钮叫「生成剪映草稿」。记住本机输出偏好后，下一次从入口按同样设置快捷生成；发现阻塞问题或需重新选择目录时才展开相应步骤。提供「调整导出设置」入口。首次配置和异常处理需要交互，不把“一键”理解成隐藏必要问题。

执行中显示检查素材、复制素材、处理定格、生成草稿、加入剪映等实际阶段；可取消，不展示虚假百分比。完成后显示草稿位置、实际导出的片段数、需要手动处理的项目，以及「打开剪映」「在访达中显示」。只有已验证直达能力时才把按钮叫作「打开草稿」。

沿用现有弹窗、按钮、主题、键盘焦点与 Esc 规则；导出过程中关闭弹窗不能让任务和提示失控。问题可点击定位原句或素材。禁止把分镜描述自动烧成画面，也不要把错误卡片塞进正常成片。

## 5. 首版必做、选项与后续边界

首版的核心承诺是：**按分镜台现有主画面预览排布生成可编辑的粗剪草稿**，保留时间关系，并把不能自动表达的内容说清楚。

| 内容 | 首版行为 |
| --- | --- |
| 本地视频、静态图片 | 必须支持，独立片段，保留主画面顺序与时间 |
| 共用画面、句子范围、手动位置 | 必须支持，复用现有排布逻辑 |
| 视频入点/出点、同素材多处复用 | 必须支持，引用可复用，片段 ID 独立 |
| 定格补满、预览中的自然停顿 | 必须支持，采用已验证且可重开的表达方式 |
| 已关联口播音频或视频中的音轨 | 默认包含，作为独立音轨；视频画面不自动铺成 A roll |
| 素材原声 | 默认关闭，与当前预览一致；可提供统一开启选项，默认有口播也不混入原声 |
| 当前逐句口播字幕 | 可选，默认关闭；开启后必须是可编辑文字轨，同时附 SRT |
| 备选素材 | 默认不进时间线；可选复制到草稿素材区，经验证不支持素材区登记时仅随交付附带并明确说明 |
| 叠加素材 | 当前预览未实现完整叠加排布。首版单独列出，可随草稿交付但不擅自上轨；有叠加时必须提示“需在剪映中安排” |
| 只有链接的素材 | 不把 URL 当本地文件；先通过现有下载/保存流程落为本地素材，再导出 |
| AI 动画、结构特效的文字描述 | 没有关联实际媒体时只写交接说明，保留对应空缺，不假装已经生成动画 |
| 转场、滤镜、配乐自动匹配、智能节奏重剪 | 不属于首版 |
| 双向同步、修改已有剪映草稿、回读剪映修改 | 不属于首版；重新导出生成独立新草稿 |
| CapCut、Windows、跨机器任意搬动无需修复 | 未验证不承诺 |

叠加属于明确的后续扩展：需要先在分镜台统一定义起止、层级、位置、缩放、透明度，并让预览与导出共用模型，再接入剪映上层轨道。不要只在导出端发明布局，让分镜台与剪映呈现不同画面。

原素材尽量整文件复制，裁剪通过草稿源区间表达，保留进入剪映后继续修剪的空间。不要默认把每段视频重新编码，或只剩不可延长的裁剪片段。已下载的短片以当前真实本地文件为源，不能再次套用网站原片的绝对时间，造成二次偏移。

## 6. 时间与画面语义：最重要的正确性要求

### 6.1 一份排布真相

从已保存项目的不可变快照开始，用 `buildTimeline`、`buildPlaybackUnits` 和既有画面规则构建通用导出计划。使用 `projectData` 等现有项目选择边界并真正深拷贝，不能持有实时 `state` 的嵌套引用。

不能用当前筛选结果、DOM 排列、文件名排序、候选清单排序或 `Object.values(assets)` 代替最终画面顺序。共用画面只处理一次，素材在不同镜头使用则保留每次使用。

`layoutShot` 的片段时间相对镜头，导出目标时间必须加镜头绝对起点；`clip` 的时间相对源文件，两者不可混用。`off`、`at.of` 失效后的退回规则、旧项目未分配素材的兼容选择，都沿用当前规则。不要重新实现一套近似排序。

### 6.2 排布区间与实际播放区间不同

只读取 `layout.items` 不足以完全重现预览。`heldThrough` 会在自动排布的句间停顿中延续前一画面；`previewItem` 还处理边界容差；`playback-view.js` 中视频继续从源入点推进，到出点后保持末帧。

因此要构建可计算的“有效播放区间”，明确静态图延续、视频继续播放、视频到出点后的定格、真正的空白。优先在 core 层抽出必要的纯计算，让预览与导出共享；不要复制整个播放器或按每帧循环采样全片来猜区间。抽取后须有预览回归证明。

检查镜头内停顿、镜头之间停顿、开头空档、录音尾部。它们不一定遵循同一个延续规则，要按当前真实预览核对，不把所有空档统称停顿并填满。

### 6.3 留白和定格

- 用户手动留白保持原绝对位置与时长；缺素材的时段也不压缩，后续画面不提前。
- 超出镜头的片段按现有有效可见范围处理，排不下的条目列入问题；不能把 `slotEnd` 无条件当作实际播放结束时间。
- `fitDone` 的当前用户含义按“定格补满”处理。正常视频以 1 倍速到选定出点，再延续末帧；不得擅自变慢、循环或拉伸成变速。
- 优先使用经过实机验证的原生定格机制。若不能稳定表达，可将正常视频与生成的末帧 PNG 拆成相邻两个独立片段；在报告中记录拆分，生成图片计入本草稿素材。
- 抽帧位置必须是选定源区间内最后一个可解码画面，不是整个视频的末帧，也不是出点之后一帧。处理旋转、方向和 VFR；不能用固定减 1 秒或黑帧充数。分镜台现有预览约 0.04 秒的末帧容差需要纳入对照解释。
- 没有选择定格补满时，不得为了填满画面自动生成定格。既有自然停顿的播放延续需单独按预览规则解释。
- 目标剪映的主轨行为必须验证会否吸附消除空档。若需兼容处理，使用已验证的保时方案，并确保最终可编辑、无额外可见文案。

### 6.4 精度与异常

中间计划建议统一为整数微秒，项目原始秒数保持不变。帧率用明确的有理数表达；若目标格式需帧对齐，对绝对边界统一量化，再用 end-start 算长度，相邻区间共用同一个边界。不要每段分别四舍五入后累计。

要求总时长和每个可视切换点误差不超过目标帧率的一帧，长项目也不能累计漂移。源入出点应落在可解码边界内；量化后为零长度的片段不能默默丢失。

对非有限数、负时间、反向区间、源区间越界、不可解释的主画面重叠给出明确诊断。正常边界容差与错误重叠分开处理，不能为了让单轨合法偷偷改变顺序。由于估算或字幕异常造成的时间冲突要定位到句子，让用户修正。

时间来源要如实显示。存在部分字幕时间、低置信或插入句推算时，不能仅凭 `timeline.source === 'srt'` 就宣称全片逐句精确。

### 6.5 音频、字幕和画布

口播从项目当前定义的全片起点开始，保留实际时长及尾部，不逐句切碎后重新拼接。源是视频时验证目标版本能独立引用音轨；若需提取音频，明确处理步骤、工具需求和输出文件。

字幕开启时以当前句子文本和同一时间轴为依据，每句一个可编辑条目；不从可能陈旧的原始字幕 cues 覆盖当前改稿。无准确字幕时间时标明“按估算时间生成”。正确转义换行、引号、中文和特殊字符。首版仅做简洁基础样式，不做逐字高亮；SRT 是附加交付，不得拿它代替承诺的文字轨。

画面默认等比完整适配所选画布，居中且不拉伸，不自动裁掉主体；现有预览适配样式需核对。如果提供填充裁切选项，必须由用户明确选择。正确处理竖屏、旋转信息、透明图片。GIF、HDR、特殊编码不默认视为已支持：分别识别、验证、必要时提示转换，不能把动态图悄悄变首帧。

## 7. 架构设计：隔离剪映格式，复用分镜规则

推荐数据流如下，名字可以按实际职责微调：

```text
项目只读快照 + 导出选项
          ↓
现有时间轴 / 画面排布规则
          ↓
通用 ExportPlan + 问题列表
          ↓
本机检查 / 素材复制 / 派生素材生成
          ↓
剪映 11.6 适配器生成草稿结构
          ↓
校验 / 原子提交 / 已验证的草稿登记
```

建议边界：

| 层 | 建议位置 | 只负责 |
| --- | --- | --- |
| 纯数据计划 | `renderer/src/core/edit-export-plan.js` | 显式输入转通用片段、轨道、素材引用、问题，不读状态/DOM/文件系统 |
| 应用编排 | `renderer/src/app/edit-export.js` | 保存与快照、来源身份、预检与执行生命周期；不生成私有草稿字段 |
| 界面 | `renderer/src/features/jianying-export.js` | 弹窗、设置、进度、定位问题；通过应用层和 native 边界调用 |
| 原生边界 | `renderer/src/platform/native.js`、`electron/preload.js` | 窄接口与事件解绑 |
| 系统入口 | `electron/ipc-jianying.js` | sender 校验下的 IPC 参数验证、任务 ID、取消和进度 |
| 输出任务 | `electron/jianying-export.js` | 探测、复制、提交、清理和进程状态；注入文件/媒体工具方便测试 |
| 格式适配 | `electron/jianying/` 内按必要职责拆分 | 已验证版本的 schema、能力、登记方式和结构校验 |

不要为了“架构优雅”建立庞大的插件框架；一个清楚的通用计划、一个适配器接口、一个文件任务就够。也不要把一千行实现塞进 `import-export.js`、`main.js` 或播放器。

通用计划应含 `schemaVersion`、快照来源 ID/版本、标题、时间来源、画布/帧率、总时长、素材表、轨道与片段、派生素材需求、结构化问题。片段至少有独立 ID、来源画面/句子/素材使用引用、目标起止、源起止、播放方式、音量。未知 JSON 只属于剪映适配器，不进项目数据。

随机 ID 和生成时间由边界注入，让纯计划和序列化可重复测试。素材文件可去重，片段使用不可去重。派生定格素材按“源文件身份+源帧位置+输出规格”去重，不仅按素材 ID。

不要让 core 读取 `state`、`window.native`、DOM 或 Node 文件系统；渲染层不能直接调用 Electron、启动命令或写文件。考虑 ESM/CommonJS 边界，使用可序列化计划传输，不通过拷贝业务函数解决加载问题。

## 8. 与现有功能的耦合约束

1. **保存与撤销**：导出前调用现有保存入口，然后捕获快照。导出本身不修改句子、素材路径、裁剪、定格、候选状态，不创建业务撤销项，不发 `project-committed`。失败不得破坏当前编辑。
2. **并发编辑**：异步任务绑定 jobId、projectId 和快照身份。导出中换项目、改稿、删素材或收到协作修改，不能把两个时刻混成一个草稿。完成提示对应原项目；提示“基于开始导出时的内容”即可，不强制锁住编辑。
3. **素材探测**：探测真实时长、分辨率等只用于验证及适配；不能后台改写原项目。若新探测时长会改变当前自动排布，应提示通过现有素材更新流程确认后重新导出，而不是偷偷用另一份排布。
4. **视频审核**：只按当前有效本地素材引用导出，不从候选的旧网址或原片时间重建。通过、备选、拒绝、待下载状态不被导出改变。不要复制审核下载 UI。
5. **协作**：电脑上的剪映路径、草稿目录、导出历史和任务进度均为本机状态，不广播给协作者。另一台电脑的绝对路径不能视为本机可用文件；引导现有取文件流程。首版不改协作协议。
6. **项目数据**：目标目录和设备配置保存在本机设置边界，不加进共享项目字段。确需新增项目级创作字段时，必须在 `PROJECT_FIELDS` 登记存储/交换/撤销/协作及路径改写策略，不能只加 UI 状态凑功能。
7. **项目包**：分镜台项目包与剪映草稿是两个格式。可以复用安全路径、流式复制和空间检查工具，不改变原有 JSON/ZIP 的含义，不把剪映草稿误识别为分镜台项目。
8. **其他导出与播放**：PDF、MD、CSV、项目包、句子范围、轨道拖动、撤销和连播保持原有行为。必要的共用规则抽取要用回归证明，不能顺手大改无关模块。

## 9. 素材、写盘与兼容降级

预检区分三种问题：

- 阻塞：必需文件失联或无权读取、源区间非法、必需媒体无法处理、磁盘不足、目标版本不支持、索引不可安全更新、无法生成要求的定格。
- 需确认：尚未下载的链接、用户希望带缺项导出、存在无法自动上轨的叠加；逐项说明后才能继续降级。
- 提醒：估算时间、用户有意留白、未关联画面的 A roll、未选择的备选。不要把缺画面描述等文档交付问题无差别变成剪映导出阻塞。

默认严格处理必需媒体。用户明确选择“保留缺项继续”时，用原时段留白、保留后续绝对时间并生成报告，结果必须称“已生成，含 N 项待处理”，不能显示无条件成功。未选择字幕或口播时，不因缺少这些可选项阻塞。

所有输出放到本次唯一新建的草稿目录。草稿同名时产生独立 ID 和可辨识名称，既不覆盖已有草稿，也不把旧草稿自动删除。用户在剪映继续编辑后的成果绝不能被下一次分镜台导出覆写。

先写目标父目录内的隐藏临时目录，完成素材与结构校验后再同卷重命名提交；绝对素材路径应指向最终位置，不留临时目录路径。考虑复制中磁盘满、源文件变化、外置盘断开、目录权限和取消。媒体使用流式复制与有限并发，不把整个视频读入内存。

文件身份、Unicode 文件名、同名不同文件、空格、引号、`#`、`?`、长路径都要正确处理；绝对路径与 file URL 只在对应边界转换。路径穿越、符号链接逃逸、覆盖既有文件必须防住；子进程使用参数数组，不拼接 shell 命令。

取消只能清理本次任务明确拥有的临时产物。提交后新草稿就是用户工作数据，失败回滚和后续清理不得删它，更不能递归清空目标草稿库。应用重启后只清理有本任务所有权标记且可证明未提交的临时目录。

进度、取消、结果事件绑定任务与发起窗口；跨窗口和换项目不能串台，监听器要解绑。限制重复点击导致的重复任务。

需调用媒体工具时复用现有探测机制，新增抽帧等能力也要有独立可取消接口。工具缺失应只阻塞实际依赖的操作，不因为少 ffmpeg 就禁止不需要转换的基础草稿。不要把 Python、pip、开发者命令行环境作为普通用户使用导出的前提；若选择外部库，先核查许可证、固定版本、打包体积与实际 Mac 支持。

“保存草稿文件夹”默认保证它在最终保存位置可用。相对路径和跨机路径重写未经实测时，不宣称随意移动文件夹仍可用。若首版没有可验证的便携机制，交付说明中写清放置位置与修复方法，后续再扩展搬家导入。

输出附带简短 `导出说明.md` 和机器可读导出报告，记录目标版本、生成时间、时间来源、统计、缺项、必要降级及定位信息。技术报告不要混入剪映必需文件，也不复制用户设备标识或帐号信息。格式样例及测试数据使用合成素材和脱敏字段。

## 10. 必须执行的验收用例

请新增有意义的行为测试并接入现有测试入口，不能仅断言“JSON 有 tracks 字段”，也不能把实现输出原样当成期望值。

### A. 固定时间样例（可手工核算）

构造总长 12 秒的测试项目，用有效的手动位置明确排布，避免默认自动排布改变本样例：

| 时间 | 期望内容 |
| --- | --- |
| 0–3 秒 | 视频 A，源片 5–8 秒，1 倍速 |
| 3–5 秒 | 图片 B |
| 5–6 秒 | 用户手动留白 |
| 6–8 秒 | 视频 C，源片 10–12 秒 |
| 8–12 秒 | 视频 C 选定出点前的末帧定格 |
| 0–12 秒 | 独立口播音轨 |

C 的使用记录明确启用定格补满。验收要求：剪映中总长 12 秒、B 不抢占留白、C 不提前到 5 秒、C 不变速或循环、画面素材原声默认关闭、口播只出现一次。PNG 定格方案允许 C 拆成视频和图片两个片段，但视觉结果一致且独立可编辑。

### B. 纯计划与时间测试

- 同一画面内 3 个主素材，调整先后、指定句子范围后，导出顺序与预览一致。
- 3 句共用画面不会生成 3 份重复片段；同一个视频在不同画面分别截取不同区间，两次使用都保留。
- `off`、旧项目未分配角色回退、`at.of` 失效、部分手动位置混合自动位置，结果与现有规则一致。
- 自动句间停顿正确延续；手动留白保持；未配素材的句子不被前一视频错误填满；开头和录音尾部不丢。
- 分别覆盖没有音频的语速估算、按音频总长推算、完整 SRT、部分 SRT/低置信及对齐后新插入句子。
- 选定源片段小于时间槽：未定格时留白；定格时正确延长；过长时按可见区间处理且不越过镜头。
- 非法时间、重叠、量化后零长和越界能定位诊断，不静默改稿。
- 30 分钟以上、数百片段项目，在不同已支持帧率下边界/总长误差不累计超过一帧。
- 规划前后项目对象深度一致，撤销栈和协作提交数量不变；任务中切换项目仍使用原快照。

### C. 文件与任务测试

- 中文/空格/特殊字符路径，同名不同源文件，多次引用去重，源区间从已下载短片正确起算。
- 失联、无权限、未知时长、损坏媒体、动态图和不支持编码都得到正确分类。
- 复制期间取消、磁盘不足、源文件变化、目标目录变更，不留下假成功草稿，不删除既有数据。
- 连续导出两次各自可用；第二次不会改变第一次在剪映中的编辑结果。
- 完成草稿的素材引用只指向有效最终路径；默认复制模式下，移动测试源文件后草稿仍能播放。
- 共享索引冲突/不可解析/剪映运行状态均按实证策略处理；其他草稿条目与未知字段保持。
- IPC 参数校验、任务身份、重复点击、事件解绑与取消边界有覆盖。

### D. 真实 Mac 剪映 11.6.0 验收

1. 从分镜台真实导出入口生成测试草稿，不能只跑底层脚本代替产品流程。
2. 在剪映草稿列表找到它并打开；检查媒体全部在线，分辨率与帧率正确。
3. 对照固定样例检查切换点、源入点、留白、定格、静音与口播同步，至少播放跨越每个边界。
4. 在剪映手工移动或裁剪一个片段，保存关闭后重新打开，确认编辑保留。
5. 关闭并重新启动剪映，再开草稿，确认没有被旧镜像时间线覆盖回空项目。
6. 使用测试素材验证复制模式的独立性；仅在隔离测试目录移动测试源文件，不移动用户真实素材。
7. 打开可选字幕与备选素材模式，再验证文本可编辑、备选不出现在正片。
8. 保留至少三张真实证据图：分镜台导出摘要、剪映中对应时间线、重新打开后的关键片段；录下目标应用版本与样例身份。截图不能只证明草稿列表里有一个名字。

没有这组实机证据，结论只能是“实现完成，真实剪映兼容性待验收”。11.4 的第三方报告不能代替 11.6 验收，测试替身不能代替目标应用。

## 11. 推荐实施顺序

1. 阅读现有约定和代码，记录当前修改，重新确认安装的剪映版本。
2. 验证独立最小草稿，形成目标版本能力表与导入/登记结论。
3. 实现纯导出计划与固定样例测试，先验证时间、顺序、留白、定格语义。
4. 实现版本适配器、文件任务、IPC 和取消，验证失败路径。
5. 接入精简导出界面与本机设置，覆盖正常、问题、取消、完成状态。
6. 完成口播、可选字幕、备选素材交付及真实剪映回归。
7. 执行 `npm run lint`、`npm run test:data`、`npm run test:ui`；如修改了协作或主题基础行为，再运行对应专项测试。按实际影响补测，不重复运行无关检查凑数量。
8. 写真实完成的更新说明、使用说明与验收报告。必要的构建只用 `.noindex` 临时目录；发布/安装遵循用户授权和 AGENTS 约定。

如果在第 2 步发现格式不通，不要先堆 UI。明确记录失败现象、尝试路径、剩余假设，并继续完成不依赖该格式假设的纯计划与测试。不要把尚未解决的问题藏进最终“已完成”。
