# DeepSeek 审查复核与修复

复核对象是 `Claude outputs/bug审查_DeepSeek.md` 与当前 2.0.0 工作区。原报告保持原样。根据源码、隔离测试和最小复现决定修复，版本号不变。

| 报告条目 | 复核结论 | 处理 |
| --- | --- | --- |
| P2-1 异常百分号地址导致导入抛错 | 属实 | 地址解码失败返回格式错误，合法 `%25` 正常通过 |
| P2-2 后台重画替换编辑器 | 属实，具体失焦行为受窗口焦点影响 | 所有后台重画共用编辑保护，输入结束后读取最新数据；需要重建时先提交，防止重入 |
| P2-3 更新写盘错误未接入 Promise | 属实 | 下载改为流管道统一处理读取、写盘、背压和取消；失败清理临时文件 |
| P2-4 ZIP 大小声明可以被虚报 | 属实，报告建议的大小估算法不正确 | 项目解压限制实际输出并核对声明长度；素材超过预算的块在写盘前拒绝 |
| P3-5 批注 MD 丢失时间与返工信息 | 属实，选择保留既有批注交换用途 | 补齐隐藏元数据；重映射镜头起点和素材引用；改稿新增句子的时间引用也跟随编号 |
| P3-6 关闭口播后重新起播 | 属实 | 开关同步更新当前播放会话，旧播放器事件不影响新会话 |
| P3-7 输入法中间态进入备注 | 表格输入处理确实未过滤组合事件 | 组合期间不提交，确认后保存；后台刷新保留当前编辑器 |
| P3-8 停止后元数据回调仍能播放 | 属实 | 清监听、清媒体地址，并检查播放会话身份 |

额外确认并修复了两项待验证观察。原解码名额交接可通过正常 Promise 时序稳定复现同时执行五个任务；现在直接把名额交给排队任务，保持四个上限。镜头拖动补上取消、捕获丢失和关闭清理，取消后不会阻塞后续排布刷新。

报告对返工信息保留的判断有遗漏：JSON 中虽然携带素材返工标记，`hydrateProjectAssets` 重新载入时仍会丢掉它。因此同时补齐素材使用记录的清洗与复制，覆盖重新打开、JSON 和 MD 回读。

报告将若干既有代码缺陷描述为本轮整理带入，不作为归因依据。复核重点是当前问题是否存在和修复后行为是否正确。

新增回归覆盖异常地址、JSON / MD 往返、写盘失败、虚报 ZIP 大小、解码竞争、后台重画、输入法组合事件、口播开关、迟到播放器事件与拖动取消。界面测试使用隔离项目；播放器事件测试使用可控替身，输入法测试使用组合事件，不能等同于覆盖所有实际输入法和解码器。

最终验证通过：99 项数据回归、16 项协作规则回归、40 项主进程回归、544 项界面自测、13 项双实例协作测试，以及主题、架构、代码检查和格式检查。
