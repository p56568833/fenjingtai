# 分镜台代码维护

界面在 `renderer/src`，系统能力在 `electron`。`core` 处理数据规则，`app` 处理状态和业务操作，`ui`、`features` 处理显示和交互，`platform/native.js` 负责跨进程调用。入口 `main.js` 只负责装配。

## 数据与界面

- `core/` 接受显式输入，负责数据规则，不读取页面和共享状态。
- `app/state.js` 只保存当前项目；`project-queries.js` 管句子、类型与时间查询，`search-queries.js` 管搜索，`project-load.js` 管加载与迁移。
- `app/view-state.js` 保存选区、筛选和视图；选择操作位于 `app/selection.js`。事件直接从 `events.js` 引用，不通过状态模块转导出。
- 项目字段的保存、交换、撤销和协作策略统一定义在 `core/project-data.js`。
- `ui/` 和 `features/` 通过应用操作修改项目，不自行保存或创建撤销记录。
- `platform/native.js` 是渲染层访问系统能力的入口。

## 添加项目字段

在 `core/project-data.js` 的 `PROJECT_FIELDS` 登记字段及默认值，明确是否参与普通编辑撤销，以及是否属于共享项目信息。加载、保存、项目 JSON 和撤销快照都从这份清单选择字段；协作的项目级字段也从这里取得。

句子、素材、候选属于独立集合，仍由各自模型校验和同步。新字段若包含本机路径，需要同时实现共享形态与本机形态转换、项目打包时的路径改写。不要把协作密钥、连接状态、界面选区放进业务字段清单。

导入顺序是项目默认值和基本结构校验、句子编号与引用修复、素材和候选清洗、载入。已有文件格式保持兼容；改变格式时需要明确版本和迁移规则。

## 修改项目

常规数据操作放在 `app`，通过 `changeProject(label, mutate, options)` 提交。`label` 决定是否记录用户撤销，不影响失败恢复。`mutate` 必须同步；返回 `false`、返回带 `error` 的结果或抛异常都会恢复修改前的数据和对象引用。

连续输入备注、审核意见、返工要求，以及标题与文字编辑，使用 `editProjectFields(label, patch)`。`core/project-edit.js` 先校验所有目标和字段，只捕获涉及的值，再一次写入；失败恢复原字段和对象引用。仅允许明确列出的非结构字段，素材、分组和字幕等复杂操作仍走完整事务。编辑会话第一步记录完整撤销快照，后续输入不重复扫描整份项目。

导出前使用 `saveCurrentProject()`，不发布项目修改通知，不重建时间轴。后台任务通过 `storage.projectForId(id)` 取得原项目，避免各处重复判断当前项目与库内项目。

数据规范化属于修改阶段。成功后才记录撤销、安排保存、广播业务事件和提示。失败恢复会使派生查询缓存失效。正在进行的任务通过项目和候选身份定位结果，失败操作不能破坏这些引用。

文件和网络操作先异步取得结果，再以启动时的项目 ID 调用修改入口；在回调中确认原对象仍然匹配。外部文件写入和其他系统副作用不能依靠内存回滚恢复，应在校验成功后执行。

素材路径镜像在提交入口统一同步。业务操作只修改素材库与使用记录，旧项目迁移保留在加载与导入边界。

`project-committed` 描述一次完成的修改，包含项目、来源、变动字段、句子字段、受影响的句子与素材使用范围，以及结构、时间、素材和候选是否改变。表格、审核页、播放组件和相关侧栏订阅同一次提交；刷新范围由 `core/project-refresh.js` 根据实际变化决定，业务操作不再手动广播 rows、marks、notes 等刷新事件。保存、改名和备注变化不再让时间轴缓存失效，撤销和远端同步也发布同样的变化说明。

筛选、搜索和布局变化使用 `view-refresh`，不伪装成项目修改，也不使时间轴缓存失效。`update('rows')` 仅作为加载、导入或外部整体替换的保守入口，发送一次完整变化说明。常规编辑必须使用 `changeProject` 或受限的 `editProjectFields`。

备注与标注走局部更新，素材调整更新对应画面的卡片、轨道和统计；结构变化、计时变化和未知句子字段使用保守的块更新。输入中的内容等待失焦后刷新，未改变的句子和审核播放器节点保留。候选重置通知先清理旧展开状态，再发布项目提交；跳句等交互通知在提交之后执行。

## 播放与审核

审核入口 `video-review.js` 装配交互；`review-navigation.js` 负责切换与延迟跳转，`review-render.js` 负责增量绘制，`review-workflows.js` 负责导入反馈和返工交付。卡片和候选预览由入口创建实例并传入宿主节点查询，截图任务绑定自己的宿主，下载进度通过事件交给宿主绘制，不跨模块寻找整页节点。

`core/review-index.js` 一次建立句子、画面、章节和候选索引，`review-model.js` 按项目查询版本缓存。待审判断不再逐候选扫描整份候选列表；原地数据修改必须经过项目提交，才能统一推进查询版本。

- `playthrough.js` 管理连播弹窗；`review-playback.js` 管理审核页实例。
- `playback-view.js` 创建播放视图，每个实例持有自己的媒体和轨道组件。
- `playback-clock.js` 保存本实例的播放位置，播放时借用共享口播设备；暂停后保留自己的时间。
- `shot-track.js` 管理选中、拖动、裁剪和提交；`shot-track-html.js` 生成轨道内容。
- `core/playback-plan.js` 提供播放与轨道共用的排布和停顿规则。
- 同一审核画面更新时只替换标题和候选列表，保留播放器与轨道节点。

两个宿主各自创建实例，不搬动同一套节点。通过 `playback-starting` 协调口播设备占用，不直接操作另一个宿主的内部状态。

## 候选与协作

候选记录的通用规则位于 `candidate-values.js`；素材挂载、撤回和本地片段替换位于 `candidate-placement.js`；清单校验与导入规划位于 `candidates.js`。生产调用方直接引用对应职责的模块，`candidates.js` 保留完整数据 API 供数据测试使用。

协作入口 `app/collab.js` 装配共享服务和界面状态；配对与重连协议位于 `collab-connection.js`，副本同步与撤销协调位于 `collab-session.js`；主机发现与地址查询位于 `collab-discovery.js`；远端数据落地与刷新说明位于 `collab-apply.js`；文件传输仍由 `collab-files.js` 负责。

## 协作与撤销

`app/collab-session.js` 统一管理会话副本、未发送操作、历史标记和日志裁剪回补；连接层经会话接口访问这些能力，合法状态转换在 `core/collab-session-state.js` 中定义。`app/collab-files.js` 单独负责文件传输。文件模块通过明确的会话接口取得项目和连接，不依赖配对及重连的内部状态。

`core/collab-sync.js` 保留有限的远端操作日志。清理日志前，必须通过 `beforePrune` 将即将删除的操作补入现有撤销和重做快照，并推进快照标记。未回补的过期快照会被拒绝；不能恢复不完整的历史。历史恢复先校验，再移动撤销栈。

结束会话时先回补剩余远端修改，再解绑历史标记；新会话开始时重新绑定。不能将旧会话的序号用于新会话。整库恢复会清空失效的历史。

当前协作协议面向一个主机和一个访客。增加人数需要另行设计身份、句子编号和冲突处理。

## 剪映导出

- `core/edit-export-plan.js`：通用导出计划，只接受快照与显式依赖，输出整数微秒的片段/音轨/字幕/定格派生/问题；不读状态、DOM 或文件系统。
- `app/edit-export.js`：保存后深拷贝快照、本机预检、调用计划、任务生命周期与结果绑定；不修改项目、不产生撤销步。
- `features/jianying-export.js`：导出弹窗与进度/结果界面；命令 `jianying:export`。
- `platform/native.js`、`electron/preload.js`：窄 IPC 接口，进度/结果事件按任务绑定并可解绑。
- `electron/ipc-jianying.js`：参数校验、单任务、取消、补登记与事件发送。
- `electron/jianying-export.js`：素材复制、定格抽帧、视频口播抽音轨、暂存目录原子提交、封面/报告/说明。
- `electron/jianying/`：剪映 11.6 专用格式。`schema.js` 生成 `draft_info.json`，`meta.js` 生成 meta/索引条目，`platform.js` 探测应用、版本、草稿库与设备指纹，`register.js` 安全写 `root_meta_info.json`，`validate.js` 校验计划/草稿/索引，`paths.js` 处理命名与路径边界。剪映私有格式不得进入项目数据或共享协作字段。

## 验证

- `npm run lint` 检查模块循环、分层边界和实际代码错误。
- `npm test` 检查数据、协作规则、主进程和隔离界面。
- `npm run test:collab` 在两个隔离实例间检查同步和文件传输。
- `npm run test:theme` 检查主题交互。

重要回归包括失败恢复不触发业务事件或协作写入、后台任务归属原项目、项目交换保留业务数据并排除本机连接信息、协作日志多次清理后撤销和重做仍保留对方修改。

架构检查核对生产代码、界面测试和外部测试脚本的静态及常见动态导入，检查界面直接写项目字段，并核对命令调用、菜单映射和唯一登记。命令遗漏与重复登记直接报错，避免静默失效。删除旧接口时同步迁移测试，让断言通过现用入口执行。
